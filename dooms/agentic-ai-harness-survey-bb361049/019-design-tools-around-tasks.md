An API endpoint is designed for a programmer who can study documentation. A tool is selected repeatedly by a model with limited attention.

Offer capabilities that match real work, with clear names, namespaces and descriptions of when to use them. A candidate search with useful filters is easier to use than several low-level endpoints that require obscure IDs. Keep reads and writes distinct, and mark side effects so the harness can apply policy before execution.
