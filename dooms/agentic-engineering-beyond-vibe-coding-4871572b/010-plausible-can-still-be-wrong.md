An agent can hallucinate, misunderstand a goal, misuse tools or generate working code with poor architecture. A plausible result can hide a flawed decision.

The presenter treats skepticism as reasonable. Orchestration and **verification** become central: engineers must supervise, constrain and evaluate the system, rather than accepting an answer because it looks correct.
