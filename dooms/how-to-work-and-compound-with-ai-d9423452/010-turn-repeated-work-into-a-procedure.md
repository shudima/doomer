Yan suggests making a skill for work repeated roughly weekly. A useful skill captures decisions as well as steps: a visual artifact needs inspection, a metric-producing task needs evaluation, and executable code needs an appropriate run.

Keep the main procedure focused. Templates, scripts and reference knowledge can live separately and load only when the task calls for them.
