**Illustrative example**

Choose a few pull requests with bugs your team understands. Run the available review depths and record which useful findings appear, how long review takes and how much it costs.

Prefer the setting that fits the repository’s needs. A deeper review is useful when the extra findings justify the extra time and reviewers can act on them.
