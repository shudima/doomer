**Illustrative example**

Suppose ten generated pull requests each need thirty minutes of review. That is five reviewer hours, before any fixes.

If the sprint has only two reviewer hours available, more code generation grows the queue. Reduce the batch, add review capacity or choose smaller changes. Track completed, checked work instead of treating submitted pull requests as finished delivery.
